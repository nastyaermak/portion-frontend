# Порція — фронтенд

Простий фронтенд для сайту рецептів «Порція» на HTML + jQuery. Отримує дані з бекенду через REST API і показує рецепти з КБЖВ на порцію. У завданні «Authentication. Authorization» додано реєстрацію, вхід через JWT, вихід і сторінку тільки для залогінених.

Бекенд: https://github.com/nastyaermak/portion

## Сторінки

| Сторінка | Хто бачить | Що там |
|---|---|---|
| `index.html` | усі | каталог рецептів |
| `register.html` | тільки незалогінені | реєстрація: username, ім'я, прізвище, email, пароль і повтор пароля |
| `login.html` | тільки незалогінені | вхід за username і паролем |
| `profile.html` | тільки залогінені | «Мій кабінет»: профіль і мої рецепти; адміністратор ще бачить блок «Додати категорію» |

## Як працює авторизація

- **Вхід.** Форма надсилає `POST /api/auth/login`, бекенд повертає `access` і `refresh` токени, вони зберігаються в `localStorage`. Потім фронтенд запитує `GET /api/me`, щоб показати ім'я користувача.
- **Запити з токеном.** Усі запити йдуть через функцію `api()` у `js/auth.js`, яка додає хедер `Authorization: Bearer <access>`.
- **Оновлення токена.** Access живе 5 хвилин. Якщо API відповідає `401`, `api()` надсилає refresh-токен на `POST /api/auth/refresh`, зберігає новий access і повторює запит, тому логінитися знову не треба. Якщо прострочений і refresh, токени видаляються, і зі сторінки для залогінених користувача відправляє на логін.
- **Вихід.** Кнопка «Вийти» видаляє токени з `localStorage` і повертає на головну.
- **Редіректи:**
  - незалогіненого на `profile.html` перекидає на `login.html?next=profile.html`, а після входу повертає туди, звідки він прийшов (`next` приймається тільки як сторінка цього сайту, зовнішні адреси ігноруються);
  - залогіненого з `login.html` і `register.html` перекидає на `profile.html`;
  - після реєстрації користувач одразу входить.
- **Шапка.** Незалогінений бачить «Увійти» і «Реєстрація», залогінений — своє ім'я і «Вийти».
- **Ролі.** Блок «Адміністрування» на `profile.html` показується, тільки якщо в `GET /api/me` прийшло `"is_admin": true`. Бекенд теж перевіряє права: звичайному користувачу на додавання категорії він відповість `403`.

## Як запустити проєкт

| Що | Адреса |
|---|---|
| Бекенд (Django) | http://127.0.0.1:8000, API — http://127.0.0.1:8000/api |
| Фронтенд | http://localhost:5500 |

1. Запустіть бекенд за інструкцією з його README (порт 8000) і завантажте демо-дані: `python manage.py loaddata demo`.
2. У папці фронтенду запустіть простий сервер на порту 5500:

   ```bash
   python3 -m http.server 5500
   ```

3. Відкрийте http://localhost:5500.

Демо-акаунти (пароль `portion2026`): `nastya` — адміністратор, `oleh`, `maria`, `ivan` — звичайні користувачі. Або зареєструйте новий акаунт.

Адреса API задається в `js/auth.js` (`API_URL`). Бекенд дозволяє запити (CORS) з `http://localhost:5500` і `http://127.0.0.1:5500`.
